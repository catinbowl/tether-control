Use your Linux monitor as a Mac display.

TetherControl runs on two machines. The Linux client reports its monitor geometry and accepts injected input. The macOS host creates a virtual display at that geometry and forwards your pointer, clicks, scroll and keys when the cursor crosses onto it.

The display is arranged in macOS like any other monitor. There is no remote desktop window to keep in focus.

Read the setup steps View source on GitHub

Requires macOS on the host, Linux on the client, both on the same LAN, and Rust to build.

1. Set up both machines

Build the same binary on each machine. The Linux client listens on TCP port 9420 and advertises itself over mDNS.

01 Linux client, controlled machine

  1. Build the release binary.
  2. Allow /dev/uinput access once, then log out and back in.
  3. Start the client.
cargo build --release

sudo cp scripts/99-tether-uinput.rules /etc/udev/rules.d/
echo "uinput" | sudo tee /etc/modules-load.d/uinput.conf
sudo modprobe uinput
sudo usermod -aG input "$USER"
sudo udevadm control --reload-rules && sudo udevadm trigger

./target/release/tether-control client

Overrides: --width, --height, --refresh, --name, --bind, --port, --token, --no-mdns.

02 macOS host, controlling machine

  1. Run the host from Cargo, or build a menu bar app.
  2. Allow Accessibility access when macOS asks for it.
  3. Arrange the Tether display in System Settings, Displays.
cargo run --release -- host

./scripts/bundle-macos.sh
open target/release/TetherControl.app

Connect directly with --connect <ip[:port]> if mDNS discovery fails. Use --swap-cmd-ctrl to swap Command and Control, and --token to match the client's shared secret.

Firewall: allow 9420/tcp and UDP 5353 if a local firewall blocks discovery or input.

2. What happens at the edge

The host taps events only while the pointer is inside the virtual display. Outside that rectangle, your Mac behaves normally.

By default Control maps to Ctrl, Option maps to Alt and Command maps to Super.

Pointer on MacBook
No interception. Mac input stays local.
Pointer enters the virtual display
The host sends absolute coordinates, button state, scroll deltas and key events to the Linux client. Mac input is suppressed.
Pointer leaves the display
The host sends PointerLeave and stops tapping events.
Linux geometry changes
The client sends DisplayChanged and the host resizes the virtual display.
Connection drops
The host removes the virtual display and releases held input.
Ctrl+Option+Command+Esc
Releases held keys and buttons and warps the pointer to the center of the MacBook display.

3. Code layout

Modules are grouped by role, not by operating system. A Windows host or a macOS client can be added without reshaping the tree.

The wire protocol is a compact binary format with a handshake, an optional token proof, keepalive messages and release commands.

src/
  coords.rs        absolute coordinate mapping
  discovery.rs     mDNS advertise and browse
  keymap.rs        key and modifier translation
  protocol.rs      binary messages and auth proof
  host/macos/      virtual display, event tap, menu bar
  client/linux/    display detection, uinput injection
